# MCP-сервер Confluence для Cursor

Развёртывание стороннего MCP-сервера [sooperset/mcp-atlassian](https://github.com/sooperset/mcp-atlassian)
в Docker, чтобы AI-агент в Cursor мог читать и (при снятии режима «только чтение») писать
в корпоративный Confluence.

Проект самостоятельный: он не входит в `30_mcp_cursor` и не зависит от него. Cursor подключается
к нему отдельной записью в `mcp.json`, как к шестому серверу рядом с пятью своими.

---

## 1. Зачем этот сервер и чего он не делает

**Делает.** Даёт агенту прямой доступ к вики: найти страницу, прочитать её содержимое в markdown,
пройти по дереву пространства, посмотреть историю и различия версий, комментарии. При отключённом
read-only — создать, обновить, переместить, удалить страницу.

**Не делает.** Это не публикатор документации. Односторонняя публикация из `docs/` в Confluence —
детерминированный шаг конвейера: взял markdown, преобразовал в storage-формат, положил по известному
ID. Такой шаг должен выполнять скрипт с воспроизводимым результатом, а не агент, который «решил
позвать инструмент». Поэтому `mcp-atlassian` не заменяет собственный `mcp-docs`, а стоит рядом:

- окно на чтение — агент видит, что уже написано в вики, и не дублирует;
- разовая миграция legacy-статей — вытащить существующие страницы, не поднимая свой клиент API.

Из этого следует и режим по умолчанию: `READ_ONLY_MODE=true` здесь не временная мера на период
настройки, а нормальное рабочее состояние, если писать в Confluence будет конвейер.

## 3. Требования

- Docker Desktop (Windows) или Docker Engine.
- Confluence Data Center / Server внутри периметра компании, доступный с этой машины.
- Личный маркер доступа (PAT) — как получить, см. раздел 5.
- Свободный порт 8010 на localhost.

## 4. Быстрый старт

```powershell
cd 31_confluence
copy .env.example .env
# отредактировать .env: домен, PAT, NO_PROXY
docker compose pull
docker compose up -d
docker compose logs -f mcp-atlassian
```

Признак успеха в логах — три строки подряд:

```
Confluence configuration loaded and authentication is configured.
Read-only mode: ENABLED
Starting MCP server ... on http://0.0.0.0:8010/mcp
```

Проверка живости:

```powershell
Invoke-RestMethod http://localhost:8010/healthz
```

`GET /mcp` отвечает `405 Method Not Allowed` — это норма, Streamable HTTP принимает только POST.

## 5. Получение PAT (русифицированный Confluence)

Personal Access Token — долгоживущий ключ вместо пароля. Права наследует от своего пользователя,
отзывается в любой момент без смены пароля. В HTTP уходит заголовком `Authorization: Bearer <токен>`.

В русской локализации раздел называется **«Личные маркеры доступа»**:

аватар в правом верхнем углу → **Настройки** → в боковой панели **Личные маркеры доступа** →
**Создать маркер** → задать имя и срок → **скопировать сразу**, второй раз значение не покажут.

Прямая ссылка, не зависящая от языка интерфейса:

```
https://confluence.<домен>/plugins/personal-access-tokens/manage-tokens.action
```

Если раздела нет: либо версия старше Confluence DC 7.9 (PAT там ещё не было), либо это редакция
Server, либо админ выключил функцию.

**Проверить токен до запуска контейнера** — экономит час:

```powershell
$pat = "токен"
Invoke-RestMethod -Uri "https://confluence.<домен>/rest/api/space?limit=1" `
  -Headers @{ Authorization = "Bearer $pat" } -SkipCertificateCheck
```

- пришёл JSON — токен и URL верные;
- `401` — токен неверен или протух;
- `403` — прав нет, либо режет прокси;
- `404` — не тот базовый URL, обычно забыт контекстный путь `/confluence`;
- HTML со страницей логина — перед Confluence стоит SSO-прокси, REST до него не доходит.

Значение `CONFLUENCE_URL` в `.env` — ровно то, что в этой команде стоит до `/rest/api`.
Без `/wiki` (это хвост Cloud) и с контекстным путём, если он есть.

## 6. Переменные `.env`

| Переменная | Назначение |
|---|---|
| `CONFLUENCE_URL` | Базовый URL инстанса. Для DC без `/wiki`. |
| `CONFLUENCE_PERSONAL_TOKEN` | PAT. Именно эта переменная — путь Server/DC; `CONFLUENCE_USERNAME` + `CONFLUENCE_API_TOKEN` это путь Cloud (и Basic-аутентификации логином и паролем на DC). |
| `CONFLUENCE_SSL_VERIFY` | `false`, если сертификат самоподписанный. |
| `NO_PROXY` | Хосты в обход прокси. **Обязательно**, если в Docker Desktop прописан системный прокси. |
| `ALLOW_GLOBAL_CRED_FALLBACK` | `true` — сервер применяет PAT из `.env` ко всем запросам. Без этого HTTP-транспорт работает в многопользовательском режиме и требует токен в заголовке от каждого клиента. |
| `TRANSPORT` / `STATELESS` / `PORT` / `HOST` | Дублируют флаги в `command`; приоритет у флагов. |
| `TOOLSETS` | Какие группы инструментов включены. См. раздел 8. |
| `CONFLUENCE_SPACES_FILTER` | Ключи пространств, которыми ограничивается **поиск**. |
| `READ_ONLY_MODE` | `true` — инструменты записи не показываются агенту вообще. |
| `MCP_VERBOSE` / `MCP_VERY_VERBOSE` | Уровень логов. |

Синтаксис файла: комментарий в конце строки допустим, но **перед `#` обязателен пробел** — Compose
режет значение по последовательности «пробел + решётка». Без пробела комментарий попадёт в значение.
BOM в начале файла Compose снимает сам, кодировка Windows не мешает.

### Важное про `CONFLUENCE_SPACES_FILTER`

Это **не граница прав**. Фильтр подмешивается только в CQL поиска. Получить страницу по ID из
любого другого пространства агент по-прежнему сможет — права определяет PAT, а не фильтр.
Если нужна настоящая изоляция, заводите техническую учётку с доступом только к целевому
пространству и выпускайте PAT от неё.

## 7. Подключение к Cursor

Cursor читает конфигурацию MCP из двух мест:

| Область | Путь (Windows) |
|---|---|
| Глобально | `%USERPROFILE%\.cursor\mcp.json` |
| Проектно | `<корень открытой в Cursor папки>\.cursor\mcp.json` |

При совпадении имени сервера побеждает проектный файл. Проектный действует по **открытой в Cursor
папке** — не по той, где лежит этот compose. Так что либо глобальный файл, либо `.cursor\mcp.json`
внутри рабочего пространства 1С, рядом с правилами `mcp-tools.mdc`.

Запись:

```json
{
  "mcpServers": {
    "mcp-atlassian": { "url": "http://localhost:8010/mcp" }
  }
}
```

Секретов здесь нет: PAT живёт в `.env` на стороне контейнера. Это одно из преимуществ HTTP-варианта
перед stdio, где токен пришлось бы класть в `mcp.json`.

**Альтернатива, если не хочется `ALLOW_GLOBAL_CRED_FALLBACK`:** убрать `CONFLUENCE_PERSONAL_TOKEN`
из `.env` (оставив `CONFLUENCE_URL`) и передавать токен заголовком:

```json
"mcp-atlassian": {
  "url": "http://localhost:8010/mcp",
  "headers": { "Authorization": "Token ваш_pat" }
}
```

Префикс обязателен: сервер разбирает `Bearer <OAuth>`, `Token <PAT>` и `Basic <base64>`, остальное
отвергает. Минус — PAT переезжает в открытый `mcp.json`, который легко утащить в гит.

Проверка: Настройки → **Tools & MCP** → зелёная точка и список инструментов. После правки `mcp.json`
Cursor надо перезапустить.

## 8. Наборы инструментов

Всего у сервера 98 инструментов в 25 наборах. Наборы Jira (16 штук) здесь неактуальны: переменные
`JIRA_*` не заданы, и сервер прячет инструменты, за которыми нет настроенного сервиса.

Наборы Confluence — восемь:

| Набор | Инстр. | Что внутри | Включён |
|---|---|---|---|
| `confluence_pages` | 14 | поиск, чтение, дерево, история, CRUD страниц, ограничения | **да** |
| `confluence_comments` | 5 | комментарии обычные и внутристрочные | **да** |
| `confluence_labels` | 2 | метки страниц | нет |
| `confluence_attachments` | 7 | вложения и картинки | нет |
| `confluence_templates` | 3 | шаблоны страниц, **только Cloud** | нет |
| `confluence_users` | 1 | поиск пользователей | нет |
| `confluence_analytics` | 1 | просмотры страницы | нет |
| `confluence_permissions` | 2 | проверка прав | нет |

Правила разбора `TOOLSETS`:

- переменная не задана — включаются **все** наборы (в v0.22.0 поведение сменится на шесть основных);
- `all` — все, `default` — шесть основных, можно перечислять имена через запятую;
- неизвестное имя молча отбрасывается; если **все** имена неизвестны, не включается ничего
  (fail-closed) — то есть опечатка в `TOOLSETS` выглядит как «сервер поднялся, но инструментов нет»;
- при одновременном `ENABLED_TOOLS` фильтры пересекаются по И.

`READ_ONLY_MODE=true` убирает инструменты с меткой записи не из вызова, а **из списка** — агент их
просто не видит. Поэтому при текущих настройках доступны 9 инструментов из 19.

### Бюджет инструментов Cursor

У Cursor потолок примерно 40 активных инструментов суммарно по всем MCP-серверам. При превышении
он выдаёт предупреждение, а часть инструментов агент **молча** перестаёт видеть — со стороны это
выглядит как деградация других серверов, а не как переполнение.

Арифметика для этого контура: 36 своих + 9 (сейчас) = 45. После снятия read-only станет 55.
То есть к моменту, когда понадобится запись, резать через `ENABLED_TOOLS` придётся в любом случае.
Заготовка лежит закомментированной в `.env.example`.

## 10. Эксплуатация

**Обновление образа.** `docker compose restart` новый образ **не подхватывает**:

```powershell
docker compose pull
docker compose up -d --force-recreate
```

**После правки `.env`** — тоже `up -d --force-recreate`, простого рестарта недостаточно.

**Снятие режима чтения.** Поменять `READ_ONLY_MODE` на `false`, пересоздать контейнер, перезапустить
Cursor. Сразу после этого проверить число инструментов в Settings — см. бюджет в разделе 8.

**Проект независим** от `30_mcp_cursor`: `docker compose down` в одном каталоге не влияет на другой,
общих сетей и зависимостей нет.

## 11. Диагностика

### `Invalid IDNA hostname: '*confluence.вашдомен'` — контейнер в цикле перезапусков

В `.env` остался незаменённый плейсхолдер с кириллицей, почти наверняка в `NO_PROXY`.

Механика: httpx превращает каждый хост из `NO_PROXY` в шаблон `all://*<хост>` — отсюда звёздочка.
Дальше при разборе хоста ASCII-имена идут быстрым путём, где звёздочка допустима, а нелатинские
уходят в ветку IDNA и спотыкаются уже на звёздочке. Сообщение сбивает с толку, причина — кириллица.

Падает это до всякого обращения к Confluence: fastmcp при старте проверяет свою версию на PyPI,
создаёт httpx-клиент, тот читает переменные прокси. Проверьте заодно и `CONFLUENCE_URL`.

### `401 Unauthorized` на `POST /mcp`, в логах `ALLOW_GLOBAL_CRED_FALLBACK is off`

При HTTP-транспорте сервер по умолчанию многопользовательский: PAT из `.env` используется только
для построения URL и настроек соединения, а запросы ждёт с токеном в заголовке. Либо
`ALLOW_GLOBAL_CRED_FALLBACK=true`, либо заголовок `Authorization: Token <PAT>` в `mcp.json`
(раздел 7).

Следом в логах пойдёт серия `404` на `/.well-known/*` и `/register` — это Cursor, получив 401,
пробует OAuth. Маршруты выключены (`ATLASSIAN_OAUTH_PROXY_ENABLE` не задан), беспокоиться не о чем.

### Сервер поднялся, инструментов в Cursor нет

- опечатка в `TOOLSETS`: все имена неизвестны — включается ноль инструментов;
- превышен потолок Cursor (~40 инструментов) — часть пропадает молча;
- Cursor не перезапущен после правки `mcp.json`.

### Поиск ничего не находит

- `CONFLUENCE_SPACES_FILTER` указывает на несуществующий ключ пространства;
- у учётки, чей PAT используется, нет прав на это пространство.

### Запросы к Confluence не проходят, хотя браузером сайт открывается

Прокси. Если в Docker Desktop прописан системный прокси, `HTTP_PROXY`/`HTTPS_PROXY` попадают
в контейнер, и трафик к внутреннему Confluence уходит в него. Адрес вида `127.0.0.1:10809` внутри
контейнера — это его собственная петля, а не хост. Лечится `NO_PROXY` с доменом Confluence.

## 12. Безопасность

- Порт привязан к `127.0.0.1`. Эндпоинт MCP не требует аутентификации, а за ним лежит PAT с правами
  на всю вики — публикация на `0.0.0.0` открыла бы чтение Confluence от вашего имени любому в сети.
- `.env` закрыт `.gitignore`. При коммите проверяйте, что токен не уехал.
- PAT наследует все права своего пользователя; скоупов в Data Center нет.
- Для записи заведите отдельную техническую учётку с правами только на целевое пространство.
  Иначе правки конвейера навсегда останутся в истории Confluence под вашим именем.
